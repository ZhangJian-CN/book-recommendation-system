# 验收数据与测试记录

## 演示数据

`demo_data/goodbooks` 的书名、作者和评分取自 Goodbooks-10k；显示名、分类占位值、库存和借阅记录为模拟数据。`demo_data/large` 则是完全合成的数据。两套数据都包含 100 本图书、40 名用户、800 条评分和 10 条借阅记录；来源及重建方法见 [演示数据说明](../demo_data/README.md)。`large_demo_smoke` 实际调用 `LibraryStore::load` 分别加载两套四份 CSV，并核对数量和 U00 的 Top 5 推荐。

交互演示前，先把四份 CSV 复制到另一个可写目录，再以 `--data-dir <目录>` 启动程序；不要直接修改仓库中的原始样例。

## 检索性能对比

`search_benchmark` 使用相同的 100000 次查询比较 `BookRepository::findById` 与顺序遍历；其中 10% 是不存在的编号。每个规模各运行 3 轮，报告中位耗时。计时不包含造书、建索引和生成查询。两种方法的结果校验和必须一致，否则程序退出。使用 Release 构建测得本机一次运行结果如下，单位为毫秒：

| 图书数 | 顺序查找 | 哈希查找 | 倍数 |
| ---: | ---: | ---: | ---: |
| 100 | 15.7284 | 0.8851 | 17.77 |
| 1000 | 141.402 | 3.025 | 46.74 |
| 5000 | 704.095 | 14.654 | 48.05 |

这些是本机测量值，演示时应重新运行。当前图书仓库固定使用 101 个桶；当图书数远超 101 时，每桶的平均链长会增长。报告复杂度时应写明：哈希查找在负载因子受控时平均为 O(1)，当前固定桶数实现面对持续增长的数据时不能无条件声称平均 O(1)，最坏情况为 O(n)。
